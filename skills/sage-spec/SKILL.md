---
name: sage-spec
description: Turn an agreed feature or discussion into an actionable technical specification.
---

Inspect current behavior and synthesize existing user decisions without repeating
an interview. Save to the repository's spec location, or docs/specs/<feature>.md.
Include the concrete problem, resulting user behavior, scope and exclusions,
acceptance criteria, interfaces and invariants, error behavior, migration or rollout,
and validation through observable seams. Scale detail to the actual change.
Separate established facts, decisions, assumptions, and unresolved dependencies.
Prefer existing test seams; specify edge cases that can falsify the implementation.
Do not publish issues, assign labels, or send messages unless that action is within
the user's request. A local spec is a complete deliverable when publication was
not requested. Preserve authorization already given for subsequent implementation.
